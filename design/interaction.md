## 配置图交互

画布以应用为根，分支表达真实的包含关系，例如 Kconfig 菜单到符号、设备树总线到外设。双击节点在原处显示该项的有效值、可选值和写入文件。应用文件修改先保留为草稿，可将当前文件的草稿另存副本，或检查差异后写回原工程。拖动画布空白处平移；Ctrl + 鼠标滚轮以光标为中心缩放，缩放按钮和键盘为等效入口。首次配置前展示已知输入，成功配置后再展示由 Zephyr 生成的菜单和硬件层级。[实现范围与验收](review/configuration-modules.md)

## 一个应用如何成为可构建的目标

以包含 `CMakeLists.txt` 的应用为起点。应用、板目标、构建目录、Zephyr 源码、工具链以及需要时的 sysbuild 镜像共同定义操作上下文。west 工作区是可选信息。工作台显示当前工具已经识别的板、限定符、可用构建目标与运行器，并把来源留在相应对象旁。首次配置前能确定的信息与上次构建产生的信息采用不同状态。

| 对象 | 首选依据 | 在界面中的位置 |
| --- | --- | --- |
| 应用、示例、板与 CPU | 本地应用文件、所选 Zephyr checkout 提供的板发现能力、已配置的 CMake 缓存 | 构建目标。选择器支持模糊搜索，手工 `BOARD` 的来源和最终采用值同处显示。 |
| 软件配置 | 有效的配置片段、当前镜像的 Kconfig 菜单及求值结果 | 配置图的软件分支。显示定义、类型、可见性、依赖和目标片段。搜索匹配符号与提示文字。 |
| 硬件配置 | 板级 DTS、应用 overlay、绑定、已生成的 `zephyr.dts` | 配置图中的设备节点和属性。显示完整节点路径、原值、输入文件和生效结果。只读属性说明原因。 |
| 外部组件 | 有效 west manifest 给出仓库和 revision；模块元数据、显式模块目录和真实构建输入提供依赖证据 | 模块页区分“为何需要”“目标版本”“本地状态”。无法证明的条件保留“待配置确认”。 |
| 工具与来源 | 当前 CMake 的包发现、`ZEPHYR_BASE`、`ZEPHYR_TOOLCHAIN_VARIANT`、对应工具链变量、PATH | 工具环境。每个值可追溯到来源和作用范围。允许浏览已有工具、SDK 目录或适用的本地包。 |
| 镜像、烧录与调试 | 当前构建目录、镜像信息、构建生成的运行器元数据与实际可用目标 | 由对应构建结果进入。共享工作区中的另一个工程有自己的运行上下文。 |

组件顺序、工具名称和 CPU 资格随 Zephyr 版本变化，发现服务跟随当前 checkout。示例清单版本仅为展示数据。勾选某一板时，模块选择依据当前工程的声明和构建证据；例如 `cmsis_6` 与 `cmsis` 是分别判断的两个模块。离线情况下仍可比较本地 HEAD 和本地能解析的目标；浮动引用的远端状态另列检查时间或“尚未检查”。[Zephyr 模块](https://docs.zephyrproject.org/latest/develop/modules.html) · [west 清单](https://docs.zephyrproject.org/latest/develop/west/manifest.html)

## 动作与反馈

| 用户动作 | 即时响应 | 扩展实际实现的约束 |
| --- | --- | --- |
| 打开空文件夹 | 构建页给出“选择本地应用”和“从示例开始” | 先识别输入。发现多个应用时列出相对路径。无 west 的应用仍能直接配置 CMake。 |
| 选择新的板或构建目录 | 就近显示完整目标与来源，现有结果标为待重新配置 | 优先选独立构建目录。复用已有缓存前核对应用和板，清理目录需明确确认。 |
| 切换构建入口 | 更新命令预览并保留用户输入 | west 和 CMake 的命令由各自适配器生成；工具可用性分别检测。保留手动参数原文，展示冲突与采用值。 |
| 搜索或双击配置图节点 | 在节点旁打开配置控件，显示当前值和写入文件；键盘可从同一节点进入 | 支持平移、缩放、聚焦、独立窗口。大图先显示选中节点及近邻，可按需展开。每种配置项按真实类型选择控件。 |
| 增删改查 Kconfig | 搜索符号、选择目标片段、暂存赋值或删除该片段的显式赋值 | 删除后由 Kconfig 在下次配置重新求值。设为 n 与删除赋值有不同语义；遇到不可见或依赖约束时给出原因。 |
| 编辑设备属性 | 检查器先展示类型与绑定；变更进入目标 overlay 的差异 | 属性编辑按绑定生成合法语法。生成的 DTS 用于查看结果。复杂 phandle、数组或不明类型先提供源位置，待有可靠编辑器再开放写入。 |
| 保存、撤销、跨窗口编辑 | 所有视图显示草稿差异、修改项数和目标文件；确认后按文件保存 | 会话按应用、构建、镜像及目标文件区分。服务端持有基线与修订号，检查磁盘和编辑器是否已有修改。冲突时提供重新比对，保留草稿。退出前提示未保存的文件。 |
| 执行配置、构建、运行 | 明确当前目录与命令。运行中可查看输出、取消，失败后定位诊断 | 命令使用参数数组与运行目录；成功后读取生成物。设备烧录、调试及擦除按目标能力显示，并在连接设备前核对目标。 |
| 同步一个或多个模块 | 具体行显示目标 revision、来源、状态与进度；结束后刷新受影响行 | 使用 west 配置和清单。检查本地改动，失败的模块可独立重试。网络失败时保留本地状态与最后检查时间。 |
| 切换工具来源 | 在同一行选择自动发现、本地路径或支持的安装包，然后验证版本、平台和架构 | 网络安装由用户触发。只对当前配置生效，作用域可见；用户层全局设置需要用户显式选择。 |
| 打开指导信息 | 在对应操作旁查看用途、实际文件、实际命令及官方资料 | 长教程共用一个双语帮助入口。发布版截图与鼠标引导演示采用 1920 × 1080；生产扩展全部文案使用本地化键。 |

## 响应式布局为何如此安排

导航顺序为「构建」「工作区」「工程配置」「模块」。首次打开仍进入工作区，原型旧链接 `#tools` 与 `#workspace` 也指向工作区。所有页面使用单列功能区。环境搭建在工作区上部，即使没有 west 也可配置。本页的 west 信息位于环境下方，提供直接定位入口。原生调试侧栏由 VS Code 管理。

| 场景 | 可检查的行为 |
| --- | --- |
| 桌面及宽屏 | 加宽列表、路径、图与检查器。输入、操作和结果依次向下排列。 |
| 窄编辑器 | 控件按可用宽度换行。所有四个页面保留文字入口，路径和命令完整可读。 |
| 高缩放或展开终端 | 页面垂直滚动。长清单独立滚动，到边界后由页面接续。 |
| 大屏配置 | 图在上、检查器在下。缩放与拖动只操作画布；确认工程提交前先查看草稿。 |

## 独立工程的模块边界

未来的 `zephyr_extension` 使用自己的扩展标识、命令、本地化资源、存储和许可证声明。接口围绕 Zephyr 工程对象设计。首版从 VS Code 扩展 API、所选 Zephyr 源码及正式工具接口起步。第三方依赖逐项按其许可证记录来源；旧扩展的命令、资源、私有配置和实现代码均不作为依赖。

| 边界 | 输入与输出 | 职责 |
| --- | --- | --- |
| 工程发现 | 工作区目录、环境和用户选择 → 应用/板/工具候选及来源 | 平台路径、扫描、缓存失效。只读。 |
| 构建执行 | 明确的应用/板/构建目录和参数 → 任务、诊断、生成物索引 | west 与 CMake 各负责自己的参数，使用 VS Code Task、Terminal、Problems 和 Debug。 |
| 配置编辑 | 目标文件、基线、用户操作 → 差异、修订和保存结果 | Kconfig 与设备树各自解析。跨视图共享草稿，写入前核对目标与冲突。 |
| 模块管理 | 清单、依赖证据、本地仓库 → 选中原因、版本和同步计划 | 网络检查、下载和更新与只读发现分开。 |
| 界面 | 类型化数据快照、操作结果 → 工作台与检查器 | 一套导航、列表、状态和图形控件；界面不直接写文件或启动命令。 |

**首个工程验收样例**　用同一份本地应用分别走 CMake 与 west，选择同一板目标，暂存一项 Kconfig 和一项 overlay，重新配置并比对实际生成物。第二个样例移除 west 工具，使用已安装的 SDK 和 CMake 包配置独立应用。随后验证多镜像、非 ASCII 路径、离线模块、冲突保存和真实运行器。用这些结果决定生产界面哪些操作应启用。

## 本轮原型验证

历史五页原型曾用 Windows 的 Microsoft Edge 对环境搭建、west 工作区、构建、配置图和模块五页分别测试了 1920、1024、768、600、420、360 px 编辑区宽度，共 30 组，均无页面横向溢出。交互覆盖切换命令、模糊选板、旧结果失效、草稿保存与放弃、分离窗口同步、画布平移、候选搜索、单项选择、批量同步与本地工具路径。设计图中文字和图形保持矢量，PNG 在 1920 × 1080 直接捕获。

生产验收另行验证原生 VS Code 分离窗口、屏幕阅读器、平台工具探测、官方配置求值、真实磁盘冲突与硬件操作。原型的“构建”“同步”“保存”仅演示状态转换。

## 从新机器到设备的完整评审路线

| 阶段 | 可以在原型中尝试 | 真实扩展的完成条件 |
| --- | --- | --- |
| 主机准备 | 工作区 → 环境搭建 → 新机器 → 准备安装方案，分别选 Windows、Linux | 根据 checkout 的版本要求检查 Git、Python、CMake、Ninja、DTC 等。包管理器或手工下载均可，展示安装范围和受影响目录。 |
| Python 隔离 | 切换到 Python 环境，打开 venv、packages、west 的配置与准备说明 | 绑定同一解释器与 pip，用版本匹配的 wheelhouse 或显式联网安装。检查所需包集合和版本，再运行导入测试。仅执行 pip check 不足以证明依赖齐全。 |
| 源码及工具链 | 配置本地 Zephyr，选择 SDK 或 cross-compile，并查看生效路径 | 读取源码版本和 CMake 包，核对目标编译器、架构与实际运行版本。选定板和 CPU 后可直接使用本机 SDK 中的推荐编译器。用户可为该应用和板改选，或浏览外部 GNU 可执行文件。配置后显示 CMake 实际记录的编译器。 |
| 工作区管理 | 打开或初始化 → 本地/远端清单 → 预览命令 → 管理清单与模块 | 已有工作区只读发现 topdir、manifest.path、manifest.file；本地 west init -l 在清单仓库旁建立 .west；远端可指定 URL、revision 和目标根。更新前列明影响、缓存与脏仓库。 |
| 应用和工程参数 | 工程设置 → 从示例新建或导入 → 选择板和构建目录 → 设置参数或工程工具覆盖 | 每个应用可使用不同工具环境。参数编辑保留原文，离开设置后能在配置命令中核对作用范围。 |
| 图形化编辑 | 选 Kconfig 或设备树 → 修改 → 草稿 → 差异 → 保存 → 重新配置 | 读写隔离且可撤销；运行官方构建核对生效值。跨窗口冲突、复杂属性、受限符号、BOARD 变更使用独立验收用例。 |
| 构建、烧录、调试 | 构建后进入“烧录与调试”，查看镜像、运行器和执行计划 | 读取实际构建生成物和板所支持的目标；明确设备与映像，在 VS Code Debug/Terminal 中查看执行结果。没有真实设备的设计稿只预览。 |
| 测试与诊断 | 进入测试，查看 Twister 的测试根和平台计划 | 从实际测试定义生成矩阵；缺少硬件、不可运行、失败、取消分别反馈，支持查看日志和复跑。 |
| 无网络与恢复 | 开启离线模式，尝试远端初始化和同步缺失模块；指定未知路径后验证 | 明确缺少哪个包或 Git 对象，保留已有源码与本地修改。恢复来源或修正工具路径后只重试失败步骤。 |

安装方案展示的是评审用的一组工具和版本。原型支持工程作用域、工具来源、未就绪反馈与任务计划；实际安装、鉴权、目录浏览、串口/探针探测和系统包变更由未来插件接入原生接口。原型的中文界面用于本轮评审，正式扩展的用户界面和教程均需中英文验证。

## 构建入口、进程变量与模块获取

顶栏标识本次调用的构建入口。west 驱动 Zephyr 的 CMake 构建，CMake 则从应用、板与构建目录发起配置。两者都可能使用本机已有资源。网络策略只决定是否允许发起网络请求；正式版须在离线运行 west 前确认所需对象、工具和依赖均已就绪。初始化工作区、更新清单项目和编译分别显示步骤、版本与结果。

工作区的「构建进程环境」按变量列出本次进程的值及来源。与目标缓存相符时显示“与构建缓存一致”，存在差异时列出两份值。仅在缓存中出现的变量注明“进程未设置”。两处都缺失的常用变量可展开查看。临时采用自动识别的路径与已确认的工作区设置分别标注来源。

构建页从同一份配置输入生成「构建变量」和命令预览。首先显示 `BOARD`、生成器、用户定义及模块参数，其余变量按需展开。更改参数立即更新本次传值；再次配置成功后更新相应缓存。切换构建目录、应用或板时重新核对缓存归属。原型在内存中记录示例配置，扩展读取当前目标的 `CMakeCache.txt`。

| 模块来源 | 在原型中可操作 | 正式接入依据 |
| --- | --- | --- |
| 本工作区的 west 模块 | 使用当前工作区的有效清单筛选与勾选。未关联时显示关联入口。工作区页可读入此工作区导出的 YAML 清单。 | 保留清单 revision、路径与来源，按工作区隔离。 |
| 在线模块 | 搜索 Zephyr 官方组织的仓库，选中后在原入口识别版本与元数据。 | 以组织归属、提交和模块声明分别验证来源、版本和模块身份。 |
| 个人在线模块 | 粘贴 GitHub / Gitee 仓库首页、tree 或 blob 链接，亦可提供 HTTPS / SSH 地址。可覆盖 revision 与检出位置。 | 将网页映射到仓库、分支或标签以及模块子目录。使用该版本的模块元数据，显示识别证据及所检查的提交。 |
| 本地模块 | 输入本机目录或选择文件夹，自动读取模块名称。 | 引用已有检出，批量同步跳过本地仓库。 |

待选模块共用一个搜索框。输入名称默认筛选本地列表，点击「在线搜索」查询官方仓库，仓库链接与本机路径由输入内容识别。远端模块的目标版本、检出目录和识别结果在列表中就地展示；「新手指导」收纳入口文件规则和排查步骤。

CMake 使用 `ZEPHYR_MODULES` 显式指定工程的本地模块目录列表。west 自动发现工作区模块，额外引入的本地目录使用 `EXTRA_ZEPHYR_MODULES`。原型命令中的 `<工程根目录>` 用于展示路径解析位置；正式版必须解析成绝对目录并作为单个参数传递。离线读取 YAML 使用随原型分发的 js-yaml 4.1.1，许可证见 [MIT 声明](vendor/js-yaml/LICENSE)。[Zephyr 模块发现规则](https://docs.zephyrproject.org/latest/develop/modules.html) · [west 清单格式](https://docs.zephyrproject.org/latest/develop/west/manifest.html)

## 大屏配置窗口与来源识别验收

- “全屏配置”将当前配置图移至全屏显示的原生工作窗口，退出时送回原编辑器组。使用第二块显示器时，选“在新窗口配置”可自由移动和调整窗口大小。搜索和画布工具位于顶部，应用、板和 CPU、Kconfig、设备树与草稿检查器从底部展开，窗口切换时保留编辑状态。
- 应用支持选择、导入、构建目录与附加参数；板目标支持限定符与读取 CMake 缓存；Kconfig 支持搜索、增加、修改、移除显式赋值和导入配置片段。草稿按当前应用与板隔离，保存到浏览器内的演示工程。真实 Kconfig 定义、依赖求值与落盘仍以正式扩展的构建后端为准。
- 地址和目录共用模块名称判定规则，以声明的名称优先，界面显示证据文件。目录缺少入口、文件格式错误、版本不可访问时不能确认。地址、目录或 revision 修改后之前的识别结果立即失效。本机预览服务仅监听回环地址，读取本地模块入口或临时获取指定 Git 版本。离线模式只接受本地识别。

## 模块版本与同步决定

| 画面字段 | 含义 | 操作影响 |
| --- | --- | --- |
| 工程要求 | west 清单或显式添加时的 revision，可为 SHA、标签、分支或 HEAD。 | 保留声明原文。浮动引用另外显示已知或本次解析的 SHA。 |
| 本地检出 | 当前工作树的提交；尚未下载与未知状态分别显示。 | 正式版从对应仓库读取 HEAD。原型记录模拟检出。 |
| 本次目标 | 每个模块此次准备检出的具体 SHA。 | 默认由工程要求决定。也可显式检查指定远端分支，将检查时的 SHA 用于本次模拟同步。 |

分支尖端与工程版本不同只能说明提交有差异；不能据此判定兼容性、提交先后或是否包含另一提交。批量操作按模块分别解析，任一目标未确定时禁止确认。已核对在示例缓存中的目标可离线切回。对工程版本的永久升级应单独生成清单 revision 变更并评审。真实执行时还须检查脏工作树、本地分支、Git 对象是否可用，以及失败后的每仓库结果；演示阶段只更新内存状态。

## 调试与工程配置并排

编辑器负责源码或工程配置。左侧「运行和调试」保留当前会话的线程、栈帧、变量、监视及断点；Zephyr 视图补充应用、板目标、构建目录、默认运行器和可打开的配置文件。用户可以调整 VS Code 原生视图的位置。源文件和调试配置共用原生编辑器。独立配置窗口保留整幅配置画布。浏览器预览中的单步为示例；原生扩展通过 VS Code 启动工作区已有的调试配置。
