## 试用大屏工程配置

[打开工程配置](index.html#graph)，选择应用和板后可在新窗口配置。上方画布定位配置输入，下方检查器展示对应对象和草稿，保存前核对差异。可读入已有配置片段，在演示工程中验证保存与放弃。

## 通过地址或目录识别模块

运行 `python preview.py`，打开它打印的本机地址。允许联网后粘贴 GitHub / Gitee 网页或 HTTPS / SSH 地址。网页中的版本和模块子目录会自动解析；仓库首页默认读取 HEAD。识别时可直接编辑目标版本和检出目录。查询在临时裸仓库进行，可以使用本机已就绪的 Git 凭据。粘贴本地绝对目录即可离线读取模块入口。若要输入工作区相对路径，启动预览时用 `--workspace` 指定实际项目根目录。直接打开 HTML 时，可通过目录选择器读取本机目录，或通过代码托管平台允许的跨域 API 识别公开仓库。

识别会读取 `zephyr/module.yml` 或 `module.yaml` 声明的名称。没有显式名称时采用本地目录名；旧式模块同时具备 `zephyr/CMakeLists.txt` 和 `zephyr/Kconfig` 时也能识别。界面列出识别依据，远端来源还显示实际检查的提交。确认后才加入模块列表。[Zephyr 模块发现实现](https://github.com/zephyrproject-rtos/zephyr/blob/main/scripts/zephyr_module.py)

## 评审当前构建入口与模块来源

顶栏的 **构建 · west / CMake** 在四个页面常驻，点击可切换。离线与联网策略单独设置。选择 west 可以复用现有工作区或演示一键搭建；CMake 可以在没有 `.west` 的情况下从本地源码、SDK 和模块配置应用。

在 **工作区 → 环境搭建 → 构建进程环境** 核对变量名、本次进程的值和来源。若与示例缓存相同，显示「与构建缓存一致」，若不同，可同时查看本次值与上次配置值。展开「未设置的变量」可检查缺项。在「构建 → 目标编译器」查看与开发板架构匹配的本机 SDK 组件、改选本机工具链或恢复自动。选择外部 GNU 后可核对 `CROSS_COMPILE` 前缀。[查看工作区](index.html#workspace)

在 **构建 → 构建变量 → 编辑附加参数** 输入 `MY_OPTION:BOOL=OFF` 并应用，点「配置」后，缓存显示 `OFF`。再改为 `ON`，页面同时显示本次输入 `ON` 和上次配置的 `OFF`。展开「更多变量」查看应用、构建目录及与目标相关的其他值。浏览器在内存中模拟这次配置。[打开构建变量示例](index.html#build)

在 **模块 → 待选模块** 输入名称即可筛选，点击 **在线搜索** 查询 Zephyr 官方仓库。粘贴 GitHub / Gitee 链接或本地路径时自动识别来源；也可直接点 **选择目录**。远端模块的目标版本和本地检出目录在同一处展示、修改和确认。联网搜索只对这次操作生效。展开「新手指导」查看目录结构与识别失败的排查方法。[查看模块搜索界面](module-sources.png)

## 同步时采用哪一个提交

点模块行的「同步」或「下载」，从上到下核对 **工程要求、本地检出、本次目标**。工程要求取自 west 清单或添加模块时指定的 revision；本地检出是此工程目前使用的提交；本次目标是确认后要检出的提交。

默认按工程要求同步。若想试用上游改动，可以只把某一行改为「按分支最新」，输入分支名或使用远端默认分支，点击「联网检查」。界面显示本次查到的 SHA 和检查时间。选中多项时，每行保留自己的工程版本。确认后只改变示例检出，偏离工程要求时标为「临时版本」。再次选择「按工程要求」可切回。[查看 1920×1080 同步确认示例](module-sync.png)已检出的本地目录由其所有者管理。

## 首先搭建环境

原型默认打开 **工作区 → 环境搭建**。点“切换示例环境 → 新机器”，查看环境缺项如何影响当前应用的配置按钮。通过“准备安装方案”切换 Windows / Linux，预览离线安装所需的主机工具、Python 环境、源码与工具链。环境默认与当前工程覆盖分开；任意工具可以改来源、查看检测依据或恢复继承。正式产品须以真实探测结果判断可用性。

## 配置和构建应用

[早期方案存档 · 构建工作台](build.png)

以 `hello_world` 为例。页首使用应用名作为标题，右侧就地执行配置或构建。按构建目标、输入、操作、结果、命令预览顺序向下阅读。选板时按名称或 CPU 限定符搜索；改板后旧构建结果失效，主操作变为“配置”。两种构建入口共用应用和板目标，切换时能直接对照命令。正式产品从命令实际参数生成预览，复制带引号的参数时按当前终端处理。

Zephyr 的构建由应用发起。`CMakeLists.txt` 定义应用，`prj.conf` 配置软件，overlay 描述板级硬件覆盖。配置生成的 `.config`、`zephyr.dts` 与输入文件有不同的用途。因此工作台以应用和构建目录为中心，把 west 放在可选构建入口与工作区管理处。独立应用可使用 CMake 包发现。界面布局是本项目的原创设计。[Zephyr Application Development](https://docs.zephyrproject.org/latest/develop/application/index.html) · [Zephyr CMake Package](https://docs.zephyrproject.org/latest/build/zephyr_cmake_package.html)

## 四个入口各负责什么

| 入口 | 操作对象 | 关键决定 |
| --- | --- | --- |
| 工作区 · 环境搭建 | 主机工具、Python 环境、Zephyr 源码、SDK 或外部工具链、运行器 | 在设置旁查看来源、工程覆盖和验证状态。已有工具与本地依赖包可用于离线搭建。 |
| 工作区 · west | west 根目录、清单仓库和有效清单 | 关联、初始化、检查清单、预览全量更新与解除关联在同一页完成。 |
| 构建 | 一个应用的一次构建 | 应用、板、构建目录和参数放在同一页。配置或构建的终端复用 VS Code Task；诊断跳到 Problems。 |
| 配置图 | 指定构建和镜像的配置输入 | 图上选对象，在下方检查器改值；模型中区分文件显式值、草稿值和上次求值结果。可分离到第二块屏幕。 |
| 模块 | 当前工作区清单和应用的本地模块 | 已选在上、候选在下。搜索和分页属于候选区；下载/同步同时有单项和批量入口。 |

构建结果中的文件链接进入只读结果。配置输入中的文件链接直接定位到图上相应节点。长期偏好保留 VS Code 的设置入口。工作台页内只保留任务导航。新窗口用于需要并排看的配置图或原生文件；普通切页复用同一工作台。

## 配置图与提交边界

[早期方案存档 · 配置图与草稿](configuration.png)

图中的连线表示应用的配置层次。展开后沿菜单找到软件符号或沿总线找到具体外设；双击节点即可在节点旁编辑。按住空白处平移，Ctrl + 滚轮在鼠标处缩放。拖远后可在搜索栏旁点“定位选中节点”，或点“适应全图”查看各个展开的分支。全屏和独立窗口通过底部按钮打开配置检查器或核对草稿。示例把 `CONFIG_PRINTK` 从 `y` 调为 `n`。可先在“独立窗口”查看同一草稿，放弃后两处同步；点击“保存到工程”将本次文件标记为已改，返回构建页需重新配置。原型使用内存演示。实际文件一致性、Kconfig 依赖、多镜像与冲突约定见[交互说明](interaction.md)。

## 空间和视觉

[早期方案存档 · 不同编辑区宽度](responsive.png)

- **常规编辑区**采用单层横向导航、稳定的页首、输入与结果上下排列。操作按钮靠近它控制的对象。短页按内容结束。
- **窄于或等于 740 px** 时，收紧留白并适当折行，保留四个文字入口。模块版本移入模块名下方，单项下载仍可点击。窄到 420 px 时目录标签移到值上方。
- **低窗口**由页面纵向滚动。画布和长清单可以独立滚动；列表抵达边界后外层继续滚动。顶栏提供导航，底部终端和侧栏由用户控制。
- **明暗主题**使用统一语义颜色。绿色配合“已同步”，琥珀色配合“版本不同”，中性色配合“未下载”。正文有可读标签，等宽字体只用于路径、版本和命令。生产版映射 VS Code 的主题、系统字体、焦点和高对比令牌。
- **快捷操作**在有足够空间时常驻行内；窄屏次要维护动作可收进更多菜单。键盘可以完成相同路径。正式产品移动或编辑后应将焦点还给原控件，屏幕阅读器播报结果。

## 交互评审路线

1. 在环境搭建切换到新机器，预览 Linux 或 Windows 安装方案，模拟准备并验证。打开工作区，以本地清单初始化后查看模块。
2. 在构建页切换 west / CMake，查看命令；筛选另一个板目标，观察“构建”何时恢复可用。
3. 进入软件配置，修改值，加入草稿，分离窗口，放弃或保存。返回构建页检查结果是否失效。
4. 开启允许联网的来源策略后，在模块页搜索 `mbt`，勾选 `mbedtls`，再同步所选。上面的已选区应始终可见。
5. 在环境搭建的“源码与工具链”中为 SDK 输入本地目录。缩窄浏览器、切换主题，检查路径、操作和版本号是否仍能看到。

本轮验证对象是浏览器中的交互与版式。原生扩展的构建与文件写入验收见[当前评审](review/README.md)。硬件烧录列为独立验收项。

### 运行和调试侧栏

浏览器原型默认并排展示调试目标和工作区，可在左上角切换侧栏。启动调试演示后，选择栈帧查看示例源码，或打开工程配置，同时观察左侧会话。小屏可按需展开，独立配置窗口使用完整画布。[1920×1080 预览](debug-sidebar.png)

[原生扩展预览](../extension/README.md) 为 VS Code 的「运行和调试」增加 Zephyr 调试目标。变量、监视、调用堆栈和断点直接使用当前调试适配器提供的数据。
