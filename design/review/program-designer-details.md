# 程序设计器详细设计与评审

**简体中文** | [English](program-designer-details.en.md)

基线为 Zephyr View 0.5.27，提交 `3bff9bb`。验收场景是一条采样链。采样线程发送数值，处理线程接收后调用共享函数，显示线程等待通知。设计稿、安装版和测试应使用同一份程序图与生成器。

| 操作 | 交互与数据约定 | 验收 |
| --- | --- | --- |
| 连接两个节点 | 左侧选择上下文或对象，中央按起点、终点决定操作，右侧显示对象、方向及 Zephyr 调用。确认前允许取消。 | 从队列连到处理线程得到接收；反向得到发送。无效组合给出具体提示。 |
| 移动现有指令 | 在右侧选择现有指令、目标上下文、块和位置，整棵指令子树作为一次编辑，保留步骤 ID。 | 把已有步骤移入 else 或另一线程。目标位于自身子树、导致递归或超限时，原图保留。 |
| 复核并发设计 | 从 main 和各线程出发，沿实际引用的函数查找对同一对象的操作。给出检查结果、原因、相关步骤和修复方式。只有结构错误会阻止生成。 | 空队列上的等待缺少任何可达发送端时能定位。未调用的函数不能充当生产者，共享函数的调用者均有据可查。 |
| 回放固件 | 区分运行上下文、定义步骤、数据或许可。画布和源码按同一条记录定位。遇到缺失信息时保留未知状态。 | 两个线程调用同一个函数时能区分来源；带分支的记录可核对实际方向与源码。 |
| 更新已有工程 | 在更新入口可以用 VS Code 差异视图检查已保存的 C 和本次将生成的 C。预览不写文件；确认更新时重新核对图版本、文件归属、本地手工编辑和磁盘内容。 | 预览后放弃不动工程。图、磁盘、编辑器已有修改时，过期确认不可覆盖源码。 |

消息队列复制固定大小的数据；信号量发放和获取许可。诊断要依据初始状态、等待方式和可达操作，图上可能存在的端点不能证明真实运行已执行。运行时间、硬件行为与实际执行顺序需要分别取证。[Zephyr 消息队列](https://docs.zephyrproject.org/latest/kernel/services/data_passing/message_queues.html) · [Zephyr 信号量](https://docs.zephyrproject.org/latest/kernel/services/synchronization/semaphores.html)

## 评审记录与验收结果

| 原先可复现的现象 | 修改及验收证据 |
| --- | --- |
| 从队列连向线程仍需猜测生成哪个操作。移入条件分支要删掉并重建步骤。 | 安装版中从 `samples` 连向 `relay`，确认前可读到 `k_msgq_get`。把原有打印步骤移入 else 后，重新读取保存的图，步骤 ID 保持不变。删除非空分支或转换类型会列出将移除的子步骤数。 |
| 空队列上的接收可以永久等待，图上找不到调用同一对象的线程。 | 选中对象，可查访问步骤、所在函数和可到达的线程。QEMU 边界试验中，图外线程送入 `99` 后，等待的接收线程继续运行。图内缺少发送端是一条排查线索。 |
| 函数的输入和结果共用同一个事件，回程箭头也指向被调用方。 | 内置 QEMU 记录有 18 个事件，`scale` 入口为 `42`，返回调用线程为 `84`。另外验证了两线程共用函数、驱动返回值及跟踪关闭时的行为。旧版 17 事件的记录按原有信息与源码行号回放。 |
| 更新前难以核对生成代码和实际工程文件。 | 安装版在 VS Code 差异视图中比较将采样初值从 `42` 改为 `91` 的修改。返回设计后源码逐字节相同；确认后才生成 `91`。复核期间若图被改为 `77`，原确认即失效，关闭本次差异后可立即重新审查。含手工修改的源码可查看差异并导出副本。 |
