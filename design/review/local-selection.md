# 本机路径、文件选择与工作区识别

## 使用者看到什么

本地文件与目录在选项、候选列表、配置图和调试侧栏中统一显示为 `路径/文件`。Windows 输入框接受两种分隔符。目录选择和打开文件使用原始地址，命令参数预览保留任务实际收到的文本。

| 对象 | 首选操作 | 其他操作或边界 |
| --- | --- | --- |
| 应用目录 | 在构建目标或工程配置中点击「浏览目录…」，在系统目录窗口中选择应用 | 也可以模糊搜索已发现的应用，或输入绝对路径和工程相对路径。应校验目标目录中的应用文件。 |
| 构建目录 | 「浏览目录…」选择已有构建树，或使用系统窗口的新建文件夹功能 | 可复用已知目录。输入尚不存在的新路径时，应先确认创建目录，再采用目标。选到普通文件时提示重新选择。 |
| 开发板与 CPU | 在板目标所在行搜索板、修订号或 CPU 限定符并选择 | 该行提交完整的 `BOARD` 值。仅在需要另选 Zephyr 源码时使用目录选择窗口。 |
| 工具与 SDK | 内置 SDK 编译器随目标识别，在列表中选择。外部 GCC 可浏览文件或输入前缀。源码或 SDK 位置可通过目录选择窗口指定 | `CROSS_COMPILE` 为外部 GNU 工具名前缀。用内置开发板和 SDK 的常规流程可直接选板和配置，配置完成后核对实际编译器。 |
| 本地模块 | 选择仓库根目录或在候选区输入工作区相对路径，如 `modules/hal/vendor` | 识别模块入口后显示名称和依据。模块的相对路径以 VS Code 当前工程根解析；远端检出位置另受工作区边界约束。 |
| Kconfig 与 overlay | 「打开已有文件…」或「新建文件…」。安装版使用打开或保存窗口，按用途筛选文件。 | 新建目的地先进入草稿。保存时核对文件，避免意外覆盖原件。所选文件要参与构建须按 Zephyr 的 `CONF_FILE` 或 `DTC_OVERLAY_FILE` 规则配置。 |
| 初始工作区 | 检查 Zephyr 源码、SDK、应用及本地模块的候选和识别依据 | 能唯一确定的有效项可临时使用；冲突时选择候选。用户确认保存后才写入相应工作区配置。既有明确配置优先。 |

文件系统对象在原生选择器浏览，逻辑对象在工作台内搜索。Windows 本机可利用系统对话框创建目录；Linux、远程宿主或已开启简化文件对话框的环境由 VS Code 决定窗口的具体外观。系统对话框地址栏里的相对路径取决于当前浏览位置，插件的「输入路径」则从当前工程根目录解析。两者应分别提示。[VS Code 文件与目录选择 API](https://code.visualstudio.com/api/references/vscode-api#window.showOpenDialog) · [VS Code 保存对话框](https://code.visualstudio.com/api/references/vscode-api#window.showSaveDialog)

## 在设计稿中核对

1. 打开[工作区](../index.html#workspace)中的「初始工作区识别」。示例中有两份应用，选其中一个并临时采用，核对构建目标；点「保存到演示工作区」后查看状态。浏览器的示例登记在刷新时复位。
2. 进入[构建](../index.html#build)，先取消一次「浏览目录…」，再选择目录。检查取消没有改动；浏览器授予的目录名称可在确认框补全为绝对或项目相对位置。用「搜索应用」和「选择目标」分别确认可搜索的应用与板。
3. 进入[工程配置](../index.html#graph)，在检查器中分别打开已有 `.conf`、新建 `.overlay`。核对草稿后只保存到演示工程。再打开已保存的副本，核对内容。浏览器的「新建」只创建演示副本，磁盘原件不变。安装版的系统对话框和实际工程写入另行验收。
4. 在[模块](../index.html#modules)输入 `modules/hal/vendor` 或本机绝对路径。预览服务可通过 `python preview.py --workspace "<实际项目根目录>"` 显式指定相对路径基准，省略该参数时用浏览器目录选择器或输入绝对路径。预览服务不会猜测 VS Code 正在打开的目录。

**已验证的浏览器行为**　Windows Edge 在原有本机预览地址完成了临时采用与显式保存、绝对及相对目标路径、应用和板的模糊搜索、读取配置、返回修改草稿、保存后重开和新建 overlay。目录取得和用户取消的两条回调使用可控选择结果验证；读取已有文件通过浏览器文件选择事件验证。上述结果只证明示例状态和界面联动。

## 0.5.3 Windows 安装验收

- VS Code 在应用与构建目录的主操作中打开 Windows 系统选择窗口，允许选择目录和新建文件夹。取消选择保留原值。「输入路径…」分别用含空格的已有相对目录、工程外绝对目录及新的多级中文目录验证；仅在确认创建后生成目录。
- 真实工作区的只读扫描识别出 `applications/component_hello`、`zephyr-main`、SDK 1.0.1 和 63 份模块目录。若同名的两个副本都没有清单依据，需要显式选择。已有清单管辖的同名模块展示清单路径和另一份本地路径。识别操作不下载、勾选或构建所有模块。
- 最终 VSIX 在隔离的 VS Code 中，针对含应用、源码、两份 SDK 和一个本地模块的测试目录，验证了唯一候选临时生效、SDK 多候选、暂不保存、本地模块呈未勾选状态、再次检测及保存。磁盘上的原有设置在确认前逐项一致，确认后只新增 `zephyrWorkbench.locations`，四类路径都相对于工程根目录。[1920×1080 安装版画面](installed/detected-workspace-0.5.3.png)
- 已有设置、编译缓存、显式空模块清单、CMake 多行和注释、Windows junction 及构建目录排除经过回归。原生文件窗口测试覆盖选择已有配置、取消、新建后放弃、确认保存、文件同名和保存冲突保护。Linux 桌面对话框此次尚未实机复验。
