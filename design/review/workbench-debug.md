# 工作台、显示与调试侧栏设计评审

**简体中文** | [English](workbench-debug.en.md)

在 VS Code 中，使用者要能从左侧 Z 入口打开一个工作台，确认当前工程和构建方式，在当前功能区完成配置，并在调试时看到与本次构建对应的目标和调试器。以下项目以这个操作过程为验收单位。最新版设计将环境并入「工作区」，同页各功能区上下排列。旧版截图中的五项导航和左右面板仅用于定位已有问题。

## 配置面板的宽度与构建入口

构建目标的标签、当前值和操作共享列宽。宽面板按可用空间的 14%、45%、41% 分配。中等宽度将 76% 留给当前值，操作移到下一行。窄面板每项占满一行，路径可换行。判定依据是面板实际宽度，因此展开调试侧栏、拆分编辑器、系统缩放与单独窗口都适用。工作区信息、模块状态和工程配置也根据各自面板换行；图标、控件间距和图中文字保留可读尺寸。

构建方式单独一行，选项名为 `west` 和 `CMake`。鼠标选择用圆角底色表示。键盘焦点沿选项轮廓显示，方向键可切换选项，Tab 可移至下一控件。原生单选语义向屏幕阅读器提供选中状态。选择 west 时核对 west 程序和工作区清单；选择 CMake 时核对该应用、目标和本机工具。两种方式分别列出可配置、可构建的状态。点击未就绪的「构建」可查看所有已识别的缺项，并就地选板、选目录或打开对应设置。源码、工具链和模块也可以由 Zephyr 的 CMake 包、工具链文件及项目声明发现，具体解析结果以配置任务为准。[Zephyr 应用开发](https://docs.zephyrproject.org/latest/develop/application/index.html) · [west 构建](https://docs.zephyrproject.org/latest/develop/west/build-flash-debug.html)

0.5.5 实机验收使用 Windows 的中英文 VS Code。在 1163、1035、907、722、427 和 251 个 CSS 像素宽的编辑区中，三行值框起止位置与首个按钮起点一致，长路径和展开的选板列表均未造成横向溢出。以 `hello_world` 和 `qemu_cortex_m3` 在两个入口生成 ELF。另在空工程点击构建验证了多项提示，并复验了一次配置失败到修正、重新配置成功的过程。[已就绪的构建目标](installed/build-target-alignment-0.5.5.png) · [west 缺项和修复入口](installed/build-prerequisites-0.5.5.png)

## 入口与布局

| 编号与操作 | 设计决定及依据 | 实现证据与待验项 |
| --- | --- | --- |
| UI-01 点击 Z，再次进入 | 一个活动栏入口对应一个 Zephyr 工作台。首次进入落在工作区配置，再次进入复用已打开的工作台，保留草稿和当前任务。原生编辑器标签仍可用于关闭、移动工作台。 | 宿主按面板实例调用 `reveal`，同时监听侧栏可见性。逐次切换 Z、资源管理器、运行与调试，确认只有一个 Zephyr 编辑器。重载窗口会触发可见性事件，需单测打开普通源码时是否抢焦点。[面板生命周期](../../extension/workbench.js) |
| UI-02 工作区内配置环境 | 顶层只保留工作区、构建、工程配置、模块。在工作区内上下排列工作区信息、工具和变量等功能，工作台内不再显示模拟侧栏开关。浏览器原型的侧栏开关用来演示宿主行为。 | 已发布的 0.5.1 装机截图证明宿主去掉了重复开关；历史版本仍把环境列为一级入口。本轮 0.5.2 Windows 扩展开发宿主已核实四项入口、首次落在工作区、进入构建后导航标记对应页。正式安装包及浏览器原型的响应布局另见本轮总表。[原型](../index.html) · [既有装机画面](../vscode-environment-0.5.1.png) |
| UI-03 查找当前工程与构建入口 | 工程根、应用与构建目录可不同。顶栏显示 west 或 CMake，实际动作紧靠目标。长路径保留可读末段或可换行位置，完整路径可查询，按钮文字保持完整。 | 构建页目标行保存完整路径为提示，命令预览来自后端计划。多根目录、空工作区、含空格或中文路径都应核对中央应用与侧栏读取的是同一目标。[构建视图](../../extension/media/workbench.js) |
| UI-04 伸缩侧栏、打开下方面板 | 工具、变量、目标、产物、检查器纵向排列。表格的一行可含多个字段。控件放在所属分组，窄屏按组换行，动作不与标签重叠。长列表局部滚动，到边缘后滚轮应继续带动外层。 | 0.5.0 在约 1178、722、458、298 个 CSS 像素宽度做过碰撞检查。布局合并后须重跑。验收时另以鼠标滚轮和触控板分别试验内外两层，滚至两端后可看到前后分组。[旧版视口测试及 1080p 截图](../review-0.5/README.md) |
| UI-05 键盘选择目标 | 在应用、板与 CPU 或构建目录所在行展开列表，输入片段筛选，方向键和回车选择，Esc 返回发起选择的控件。改选开发板不得清空用户附加参数。 | 已有 west 与 CMake 两条路线选择同一限定目标的实机记录。仍应检查空候选、当前项超长、全键盘关闭后继续操作及编辑中草稿。[双入口选择记录](../review-0.5/README.md) · [行内选择器](../../extension/media/targetPicker.js) |

VS Code 建议活动栏入口承载侧栏视图，并明确建议避免用它直接打开 Webview 面板。本产品保留原生目标侧栏，并按已确认的需求在进入时联动中央工作台。这是主动采用的交互取舍。窗口恢复、显示侧栏和用户主动进入使用同一可见性事件时，尤其需要测试焦点。[VS Code 活动栏指南](https://code.visualstudio.com/api/ux-guidelines/activity-bar)

**已修复的可读性问题。** 在 Windows 的独立 VS Code 安装版工作台打开「构建 → 命令预览」，读取标签的实际前景色和面板背景色。在同一 Webview 应用共享样式修复进行配对测量。浅色主题原为 `#526970` 配 `#202e34`（2.41∶1），改为继承面板前景 `#d3dfdf` 后为 10.25∶1。深色主题相应从 8.72∶1 提升到 12.18∶1。普通字号 AA 门槛为 4.5∶1。该测量针对命令标签，不能代表整页色彩已经通过验收。[W3C 文本最低对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) · [VS Code Webview 设计指南](https://code.visualstudio.com/api/ux-guidelines/webviews)

## 调试侧栏与构建元数据

| 编号与操作 | 设计决定及依据 | 实现证据与待验项 |
| --- | --- | --- |
| DBG-01 定位调试目标 | Zephyr 侧栏展示应用、板与 CPU、构建目录、调试 runner 和会话。工程侧栏和「运行与调试」复用同一数据源，变量、监视、断点和调用栈交给 VS Code。 | 两个树视图注册同一个提供器。工作区、活动文件、调试会话或指定文件变化时刷新。尚需验证多根工作区从非 Zephyr 会话切回时的目标归属。[树与监听](../../extension/extension.js) |
| DBG-02 使用快捷按钮 | 选择构建目录、启动、刷新的入口与目标显示在一起。高频动作即使鼠标离开仍能找到，已有的全局显示偏好由用户掌控。 | 三项命令贡献在原生树标题栏，是否持续可见受 VS Code 标题栏控制。构建目录、调试会话两行本身可点击。刷新没有同等的常驻行内入口。可向用户说明宿主设置 `workbench.view.alwaysShowHeaderActions`，并对默认设置下的常驻入口另行验收。[命令声明](../../extension/package.json) |
| DBG-03 核对实际构建 | 列出 CMake 缓存确定的板和应用，runner 标明取自本次生成文件。区分“尚待配置”“上次已构建”“本次草稿”，使用户知道即将调试哪个产物。 | 读取 `CMakeCache.txt` 和 `zephyr/runners.yaml` 中的 `debug-runner`，缺失时显示占位，YAML 无法解析时提示。已构建 A、中央改选 B 但尚未配置时，须证明目标信息没有混淆。sysbuild 顶层构建还需识别每个域。[目标解析](../../extension/target.js) |
| DBG-04 选择和启动调试 | 通过工作区的 VS Code 启动配置选择调试适配器；Zephyr runner 和 VS Code 启动配置分别表述。没有启动配置时提供宿主创建入口。 | 已接入原生选择器与 `vscode.debug.startDebugging`。当前候选按 `name/type/request` 筛选，未核对适配器或 ELF 是否对应当前板，未以真机验证断点、单步、继续、停止。检查一个含两个板目标的工作区是必要验收项。[启动逻辑](../../extension/extension.js) |
| DBG-05 核对不同调试能力 | 按当前 Zephyr 构建、板和 runner 实际支持显示烧录、调试、attach 等动作。CMake 用户也可以使用现有调试适配器与已生成的 ELF。 | 当前可查看元数据并选择启动配置，无法据此证明支持所有 runner 命令或多镜像会话。要核对命令、runner 查询结果、域名及生成文件，并分别记录无硬件与真机测试。[Zephyr 构建、烧录与调试](https://docs.zephyrproject.org/latest/develop/west/build-flash-debug.html) |

调试回归建议采用同一个可运行的测试应用，先配置并生成 ELF，再从侧栏选择启动配置，在入口函数断点处检查源文件、目标 ELF、变量、调用栈，最后终止会话并确认侧栏回到空闲状态。Windows 与 Linux 均应各记录一次，使用的板、运行器或模拟器应写清楚。目前材料没有覆盖这条完整链路。[VS Code 原生调试界面与操作](https://code.visualstudio.com/docs/debugtest/debugging)
