## 打开工作台后如何走

| 入口 | 先看到什么 | 接下来怎么做 | 决定布局的原因 |
| --- | --- | --- | --- |
| 构建 | 应用、板与 CPU、构建目录、构建变量 | 就地选择目标，比较本次参数和上次缓存，配置、构建并查看生成文件。 | 快速确认要编译的目标和待生效的修改。 |
| 工作区（首次打开） | 当前目录、构建方式、环境搭建 | 检查工具、源码、工具链与进程变量的来源，需要 west 时定位到下方的工作区与清单。 | 用户能在一处确认工程所用的环境。CMake 应用也可完整使用环境区。 |
| 工程配置 | 当前目标、配置图 | 点图中的对象 → 到图下方的检查器编辑 → 对照草稿 → 保存 → 重新配置确认效果。 | 图用来确定修改对象；编辑所需的宽度完整留给检查器。专注和新窗口复用同一工程上下文。 |
| 模块 | 已选模块，下方是待选模块和搜索 | 从本工作区清单、官方在线搜索、自有 Git 地址或本地目录选来源 → 核对版本 → 单项或批量同步。 | 工作区清单记录“可取得哪些仓库”；应用和板的需求另有证据。三种版本按工程要求、本地检出、本次目标从上到下核对。 |
| VS Code 左侧调试目标 | 应用、目标板、构建目录、运行器与会话 | 选择调试配置；使用原生调试功能查看变量、断点和调用栈。 | 编辑器、终端和调试侧栏各自可调尺寸。中央页面内省去重复的侧栏开关。 |

### 三条有判别力的验收路径

1. **全离线、没有 west**。打开独立应用，选择已经准备的 Zephyr 源码、Python 与 SDK，直接用 CMake 选板、配置并构建。检查任务命令、生成的 `.config`、`zephyr.dts` 和 ELF。离线自动准备缺失工具及 wheels 另行评审。
2. **清单固定版本，远端已有其他提交**。比较工程要求、本地 HEAD 和本次目标，预览后只同步一项。断网再次打开时仍应区分“与固定 SHA 一致”和“远端分支最近何时检查”。对本地有未提交改动的模块单独验收保护行为。
3. **同一工程，变更板或应用**。保存一份自定义 CMake 参数，切换目标，再从配置图修改一个 Kconfig 显式赋值。确认选择器没有覆盖附加参数、旧构建产物没有混入、保存前原文件没有变化。最后以重新配置后的 Zephyr 输出核对有效值。

## 优先打磨哪些地方

| 优先级 | 审查发现 | 关闭条件 |
| --- | --- | --- |
| 高 | 自动选择全部必要模块仍缺证据链；单看清单不能判定某应用需要旧 cmsis 或 cmsis_6。 | 对当前 checkout、板与配置定位实际声明或构建依据；示例工程可追溯“谁依赖谁”和采用的 revision，换板可撤销原推断，同时保存手动选择。 |
| 高 | 可手工指定现成工具，离线包安装、SDK 架构和 Python 依赖完整性还未打通。 | Windows、Linux 分别用空环境、已有环境、无网络和缺包场景复验；显示检测证据、安装输入和可执行的下一步。 |
| 高 | 配置图能改片段，但完整 Kconfig 依赖和带 binding 的设备树属性需要从当前构建模型获取。 | 对照 menuconfig、最终 `.config`、生成的设备树。能区分请求值、实际值、约束及来源文件，保存冲突可恢复。 |
| 中 | west fallback 清单、分支新鲜度、多镜像、批量中断和清除模块后旧缓存仍可能让状态含糊。 | 明示范围、上次核对时间、目标域、逐项结果和参数归属，测试部分失败及重试。 |
| 中 | 原生活动栏联动中央编辑器和行内列表是特定交互取舍；需持续检查焦点、读屏、高对比和私有仓库。 | 可以只用键盘完成操作，取消后回原位。界面报告本次读到了什么；Git 凭据交由用户已配置的工具处理。 |

### 配套交付和验证边界

- **语言、平台与路径**。安装包内有中英文使用说明、命令名和部分界面翻译。模块页及其错误信息仍需补齐英文。配置中的示例路径、用户选择的运行时路径与可移植工程数据分别审。Windows 真机结果和 Linux 待验项分别记入专项表。
- **烧录、调试和测试**。支持能力由所选构建目录、镜像、运行器和调试配置共同决定。无硬件环境不能签收烧录或探针调试。Twister 测试计划和 sysbuild 域选择作为独立项审查。[Zephyr sysbuild](https://docs.zephyrproject.org/latest/build/sysbuild/index.html) · [Zephyr 测试工具](https://docs.zephyrproject.org/latest/develop/test/twister.html)
- **视觉与教学**。四页功能区在所有宽度逐块纵排。长路径和命令可换行，状态用文字和颜色共同表达。教程的实际操作截图使用 1920×1080，鼠标动作指明具体控件。当前版真机画面见[工作区](installed/workspace.png)、[构建](installed/build.png)、[工程配置](installed/configuration.png)、[模块](installed/modules.png)。
- **原型、实现与来源**。原型用示例数据，VSIX 读取本机工作区；原型的初始化按钮不能充当真实安装证据。工作台为独立工程；当前目录没有 Git 元数据，无法据此确认与历史上游分叉的提交。第三方 YAML 组件使用其随附的[许可证](../vendor/js-yaml/LICENSE)。项目自身的权利人及对外发行许可需由所有者明确。
- **变更同步**。每次变更先对应到功能编号；同步修改共享设计、原生宿主或视图、使用手册与该行的验收结果。保留旧版验收作为历史记录。带截图的安装验证与纯代码验证分别记录。
