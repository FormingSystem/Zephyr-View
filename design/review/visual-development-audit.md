## 独立编程画布的验收路径

用三个线程区分“编辑节点参数”和“设计程序”。让采样线程向队列 A 发消息，中间线程先从 A 接收再向 B 发送，显示线程从 B 接收。开发者可以从一个小示例开始，也可以增删线程与对象来搭出这张图。

1. 选择线程、内核对象和有方向的操作。在图旁显示对应的 Zephyr API 和线程内的执行顺序。消息队列发送时复制负载，信号量传递许可，互斥锁保护共享资源。三种连线应让使用者看出各自的含义。[消息队列](https://docs.zephyrproject.org/latest/kernel/services/data_passing/message_queues.html) · [信号量](https://docs.zephyrproject.org/latest/kernel/services/synchronization/semaphores.html) · [互斥锁](https://docs.zephyrproject.org/latest/kernel/services/synchronization/mutexes.html)
2. 将一次发送从 A 改接 B，再调整中间线程的操作次序。在 C 预览中检查对象参数、调用和顺序都随之变化。尝试重复命名、引用已删除对象、给信号量添加消息操作，确认能定位问题并防止导出无效工程。
3. 将图保存为副本，关闭并重新打开。核对线程、对象、数值、引用和操作顺序；修改副本后检查原件。导出到新的工程目录，并验证同名目录里已有的手工修改得到保护。
4. 还原一个可运行的图，用工作台的标准 CMake 或 west 流程构建，在仿真器读输出，再从调试器看断点处的真实值。预览中的箭头表示调用关系，线程内的操作有局部顺序；跨线程实际执行次序要靠运行记录核对。
5. 在 1920×1080 的窗口和窄编辑区走同一条路径。常用操作就近可见；折叠代码或属性后画布可利用空出的空间。拖动、缩放和定位选中节点应帮助找回移到视野之外的内容。桌面新窗口和编辑区内的独立页面分别验收。

后续扩充 FIFO、事件、工作队列时，要为每种对象补足所有权、阻塞条件、回调上下文和相应的运行例子。优先保留导出的普通 Zephyr 工程入口，使没有图编辑器的团队成员也能构建、调试和阅读代码。

## 可视化编程与运行回放

程序架构图由左侧组件库、中央画布和右侧检查器协同。可以从 `main`、线程、函数或内核对象进入，再沿所选函数的控制流查看分支、循环和调用。检查器显示应用上下文、参数和对应的 C 源码。消息队列的方向表示数据传递，信号量表示许可的发放或获取。接入外设的步骤由 C 适配函数实现，设备树和 Kconfig 继续由工程配置页维护。

本次验收保存了 `mps2/an386` 的一组 QEMU 固件实录。运行示例在静态线程间发送值 42，接收端在 `scale` 中命中条件并得到 84。程序图和控制台的构建指纹均为 `d6617b87ac27451a`，17 条记录全部映射到操作。打开下方交互示例可重复播放并逐步核对源码。播放速度只控制展示间隔。没有时间戳或序号的日志不能证明两次事件的时间差，也不能计算未被日志系统报告的丢失数。[交互示例](visual-program.html?example=firmware) · [程序图](../../extension/examples/visual-program/graph.json) · [控制台原始记录](../../extension/examples/visual-program/console.txt)

安装 VSIX 后，在独立 VS Code 配置中实测了从选择 `relay`、进入 `scale` 控制流、定位 C 函数，到打开单独的固件示例、单步查看收发值和继续播放的完整操作。首次检查发现队列与函数调用、信号量与互斥量的边标签相互遮挡。为同一列的标签错开纵向位置后，用安装包复查了四条边。演示以 1920×1080 录制，包含鼠标轨迹和双语字幕。[观看 20 秒操作演示](../../extension/guides/media/visual-program.gif)
