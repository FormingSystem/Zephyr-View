## 从一个开发问题开始

假设一个线程每次采样得到一个值，另一个线程负责处理。需要保留每次采样的内容时，选择消息队列；只需告知对方有事可做时，选择信号量；两个线程都要安全读取或修改同一份状态时，选择互斥量。依次切换这三种设计，观察哪些值跨越了线程边界，哪些操作会等待。[消息队列](https://docs.zephyrproject.org/latest/kernel/services/data_passing/message_queues.html) · [信号量](https://docs.zephyrproject.org/latest/kernel/services/synchronization/semaphores.html) · [互斥量](https://docs.zephyrproject.org/latest/kernel/services/synchronization/mutexes.html)

| 阶段 | 用户动作 | 紧邻动作的反馈 |
| --- | --- | --- |
| 选择通信方式 | 在「编程草稿」选择组件 | 两个线程之间的连线同步改变。消息与许可从生产者经对象流向消费者。互斥量由两个线程分别获取。 |
| 修改线程与对象 | 选择节点，调整栈大小、优先级或容量 | 节点显示草稿值，API 详情和源文件使用相同的生成数据。非法输入定位到字段，导出暂时停用。 |
| 验证工程 | 导出一个新的示例工程，配置并构建；在「工程分析」扫描所选应用 | 线程、调用点、对象和诊断附带源码行号；显示本次扫描覆盖范围。读工程和生成草稿各有独立的数据来源。 |
| 在断点处核对 | 在「暂停栈」选择调试会话，暂停后读取线程、帧与作用域 | 有暂停证据才显示调用栈和变量。适配器只返回 CPU 核时沿用其名称；继续运行即清除旧值。 |

## 看稿时试这四件事

1. 把消息队列容量由 4 改为 8，核对对象卡片、API 和 C 声明。任选线程，修改其栈和优先级，确认另一线程的参数仍属于它自己。
2. 切至互斥量，沿两条线找到申请同一把锁的位置。用窄窗口或键盘再走一遍。
3. 对照工程分析中的入口和普通调用，确认每条证据都能定位到相应源码，并识别分析未覆盖的文件。
4. 在离线交互稿体验标记为演示的暂停与恢复。在扩展中用真实适配器读取当前暂停的栈；切换会话或继续执行后检查旧帧是否消失。

工作台采用一页三种任务，上方选任务，关系与参数在其下展开。节点和 API 都可通过键盘选择，宽度不足时，连线方向和标签随节点改为纵向。离线稿单独提供示例分析、模拟调试和导出预览；工作台连接本地工程与实际调试会话。

已将三种组件与两种创建方式逐项核对。静态定义显示 `K_THREAD_DEFINE` 的栈与优先级。运行时创建显示 `k_thread_create` 的对象、栈、入口、优先级及启动延迟。在实际浏览器中用键盘切换任务，从消费者沿队列的访问点进入生产线程，切换暂停与继续并核对旧帧清除。中英文各通过 320、720、1280 像素宽的交互检查，另走查了 1920×1080、深色与系统高对比度显示。 [1920×1080 交互稿截图](thread-studio-1080p.png)
