# 工程配置与模块逐项评审

**简体中文** | [English](configuration-modules.en.md)

工程配置页回答“这个应用针对哪块板、哪些文件生效、我改了什么”。模块页回答“从哪里取得、谁需要、需要哪一版、本地是否满足”。同一份清单可能列出几十个仓库，只有部分会参与当前构建。图、表和操作按钮都需要说明它们作用于哪个应用、工作区和构建目录。

本次按原型、扩展实际消息处理、Zephyr 官方接口三方核对。下表中的“已接入”表示存在从界面到宿主的实现，实机验证范围另列。“部分”指可以操作但尚有明确缺口。“待实现”为交付设计和验收条件。交互总图见[工作台交互设计](../interaction.md)。

| C07 隔离草稿、核对和保存 | **已接入按文件隔离的草稿。** 原文、草稿、构建值分别显示。另存为新文件保留草稿和原件；写回工程只提交所选片段，拒绝覆盖外部修改或未保存的编辑器内容。新文件采用排他创建。跨进程重启的草稿恢复另行验收。 | 修改两个不同文件，核对保存前磁盘不变。只保存其中之一，另一份应可继续编辑；再用外部编辑器制造冲突，保存时保留两边内容，并解释下一步。 |
| C08 标准 menuconfig | **已接入。** 工作室保留当前构建的 menuconfig 入口；menuconfig 操作的是所选构建目录。外部工具产生的变化与工作室的片段草稿应明确区分，回到工作室后重新读取生效值。 | 分别通过 west、CMake 配置一个应用，打开其 menuconfig，在生成的 .config 中确认改变并核实指向正确构建目录。 |

| M04 本地目录 | **已接入。** 浏览目录或粘贴地址后识别描述文件与模块声明名；也识别含 zephyr/CMakeLists.txt 和 zephyr/Kconfig 的旧式模块。本地目录引用现有内容，单行支持查看路径。允许单机指向工作区外的模块，迁移工程时应区分共享相对路径和本机路径。 | 在断网状态加入带空格、中文、与仓库名不同的本地模块。试缺少旧式入口之一的目录，确认不能误加入。用 Windows 和 Linux 的路径形式分别验证。 |
| M05 勾选与依赖来源 | **部分。** 已选在上，待选及其搜索在下；单行可下载或同步，已选区有批量按钮。当前勾选保存于 west 工作区或 CMake 应用范围，行内原因主要显示来源。工程所需模块、声明依赖链、用户手选、清单成员四种依据需要分别标识。模块描述中的 build.depends 可提供声明证据，实际适用性还要结合所选板和本次构建结果。 | 切换应用和板后检查必要模块是否自动选择，并显示“谁需要 → 来源文件或生效配置 → 模块”。用 HC32F4A0 作样例，分别核对 cmsis_6、hal_xhsc 和旧 cmsis；仅在该工程确有证据时默认勾选。 |
| M06 版本与状态 | **部分。** 行内区分未下载、本机已识别、与工程要求一致、版本不同、要求待核对等状态。固定 SHA 可离线与 HEAD 比较；分支或标签若仅在本地解析，其远端新鲜度仍未知。设计把工程要求、本地提交、已核对的远端提交与时间分开；窄屏显示短 SHA，完整值可复制，颜色配合文字。 | 依次测试未下载、相同 SHA、不同 SHA、可移动引用远端已变、离线未知。对明暗主题及英文长标签检查可读性，并确认离线状态不会被理解成“已是远端最新”。 |
| M07 下载、更新与批量同步 | **部分。** 默认按工程要求，可显式查询分支最新。预览解析到确定 SHA，再同步；有未提交改动且需切换提交时会阻止操作。离线且目标对象已存在时无需下载。批量按项执行，后项失败时前项可能已经成功。设计应保留逐项结果和失败原因，可单独重试失败项。 | 用本地已有对象、缺失对象、脏工作树、同名但不同来源仓库分别验证。预览后改变 HEAD 应拒绝过期计划。批量第二项失败时可见第一项最终状态。 |
| M08 构建参数与撤销 | **部分。** CMake 将已选路径传给 ZEPHYR_MODULES；west 工作区保留标准发现，只将额外目录传给 EXTRA_ZEPHYR_MODULES。用户显式定义同名参数时优先。取消工作区清单项勾选只影响选中同步集合，west 仍可发现它。应在对应方法及控件旁说明效果，并为额外来源提供修改版本和移除登记的入口。 | 切换 west、CMake，逐次对照命令预览、CMakeCache.txt 与被加载模块。取消一个勾选项，再检查工作区登记、磁盘目录和默认发现各自的结果。 |

## 本轮修复与验收边界

- 已在实际字段代码验证显式 n 的显示、保留 n、切换为 y、移除、重复赋值提示、普通注释和旧设备树状态编辑；用 LF、CRLF 和无末尾换行的输入检查修改位置。
- 优先补齐 C04–C06 与 M01、M05、M06 的数据依据，再扩展控件。配置面板应能让用户看见当前值来自哪个文件、被哪个依赖约束，以及下次构建会读取哪份输入。
- 实机联测包含双窗口草稿、Zephyr 的真实 Kconfig/设备树重新配置、嵌套清单、私有 Git、批量中断、Windows/Linux 和明暗主题。本次字段回归没有覆盖这些场景；每项按上表单独验收。


## 0.5.6 板级设备树与可选覆盖

选好应用和完整的 `BOARD` 目标即可配置。工程配置图中的设备树节点应先显示开发板提供的基础描述，再显示本次实际采用的覆盖，最后提供合并后的 `zephyr/zephyr.dts`。选板后、首次配置前可以解释默认规则，实际来源以对应构建目录的记录为准。工作室只对用户选定的应用文件创建编辑草稿。[Zephyr 设备树输入和输出](https://docs.zephyrproject.org/latest/build/dts/intro-input-output.html)

| 实测场景 | 构建结果 |
| --- | --- |
| `hello_world`，`qemu_cortex_m3`，CMake | 仅传板目标，无 overlay；Zephyr 选用 `qemu_cortex_m3.dts`，生成 `zephyr.dts` 和 `zephyr.elf`。 |
| 同一应用、板和工具链，运行 west build | 使用同一份板级 DTS，生成合并设备树和 ELF。 |

## 0.5.7 选板与配置入口

- 选板后就在「板与 CPU」下方读取识别到的板级 DTS。点击文件名查看源码。完成配置后从该目标的构建记录确认输入，展开可查看本次覆盖文件及合并结果。
- 扩展侧栏与构建页都提供「配置 Kconfig」入口。图形编辑针对应用配置片段；由工具链运行的 `guiconfig` 和 `menuconfig` 针对当前构建目录。两种保存位置在入口旁说明。
- Zephyr IDE 的 Build Dashboard 可搜索符号、查看依赖、编辑片段，也能运行原生工具。本扩展保持纵向布局，复用 Zephyr 对当前目标求出的配置选项，并将修改作为草稿提交给用户选择的应用文件。[Zephyr IDE 配置入口](https://zephyr-ide.mylonics.com/reference/configuration/) · [Zephyr 交互式配置](https://docs.zephyrproject.org/latest/build/kconfig/menuconfig.html)

Windows 的 `hello_world` 实测中，在首次运行配置前选择 `qemu_cortex_m3/ti_lm3s6965`，构建页直接显示 `boards/qemu/cortex_m3/qemu_cortex_m3.dts`，可只读打开。运行配置后，同一输入显示为构建已确认。[选板后的设备树](installed/devicetree-board-preview-0.5.7.png) · [配置确认后的设备树](installed/devicetree-configured-0.5.7.png)

在 Kconfig 检查器搜索提示文字 `Thread name`，找到原应用片段中尚未出现的 `CONFIG_THREAD_NAME`。将其从 `n` 加入草稿为 `y`，核对原文件直到保存时才改变。重新配置并构建后，生成的 `.config` 中出现 `CONFIG_THREAD_NAME=y`，输出 ELF。已另用 west 和 CMake 启动官方的 `guiconfig` 与 `menuconfig`。[配置项与草稿](installed/kconfig-symbol-draft-0.5.7.png)

## 0.5.8 可交互工程配置图

| 验收操作 | 实际观察 |
| --- | --- |
| 在 Windows VS Code 展开 Kconfig、平移、缩放 | qemu_cortex_m3 的 Kconfig 一级分支展开后显示 20 个子项；平移可看到原先在视口外的节点。普通滚轮浏览，Ctrl + 滚轮在指针处缩放。另测独立窗口和深色显示。 |

| 多片段应用加入额外配置 | `mps2/an386` 的 CMake 与 west 均实际采用新登记的 .conf 和 .overlay，保留原先各片段的顺序。相对片段名含空格时，当前 Zephyr 4.5 会分开解析文件名，扩展在加入前提示。 |
| 复杂硬件配置 | 图中显示多单元属性和 phandle 的 DTS 表达式。编辑器支持状态、已有的单字符串和普通 32 位单元；binding 专用枚举和 pinctrl 等复合配置仍需工程覆盖文件。 |
