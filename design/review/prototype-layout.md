# 交互原型布局实测

**简体中文** | [English](prototype-layout.en.md)

测试对象为[工作台交互原型](../index.html)。Windows Chrome 直接加载当前工程的 HTML、脚本和样式，通过页面按钮切换功能并读取浏览器实际布局。工作区工具、工程文件和模块版本使用原型样例。截图的页面视口均为 1920×1080。

## 构建入口和变量值复测

Windows Edge 实际打开本地预览。顶栏依次为「构建」「工作区」「工程配置」「模块」，首次打开、`#workspace` 和旧地址 `#tools` 均进入工作区，`#build` 直接打开构建。在 1920、1024、768、420、360 px 五种视口分别检查构建与工作区，两页均无整页横向溢出。

工作区核对了只在缓存中出现的 `BOARD`、自动识别路径的临时来源与确认保存后的工作区来源。构建页验证了 `BOOL=OFF`、`0`、空字符串和值中含等号的参数。将布尔参数从 `OFF` 改为 `ON` 后，同时读到了本次输入与上次缓存。切换至新构建目录时上次值收起；同一构建目录切到其他应用时，页面指出缓存归属冲突，切回原应用可看到它之前的参数。此处操作使用浏览器示例数据。

## 水平溢出与缩放

每种视口分别检查了工作区、构建、工程配置、模块、按工程要求同步、按分支最新同步，合计 42 次。以文档的实际内容宽度与可见宽度比较，所有情况均无需横向滚动整页。滚动条占用的布局空间已计入浏览器实测值。

| 视口（CSS px） | 检查目的 | 有文档横向滚动的状态 |
| --- | --- | ---: |
| 1920×1080 | 宽屏、100% | 0 / 6 |
| 1536×864，像素比 1.25 | 1920×1080 在 125% 下的等效布局 | 0 / 6 |
| 960×540，像素比 2 | 1920×1080 在 200% 下的等效布局 | 0 / 6 |
| 880×720、600×720 | 编辑区变窄和换行断点 | 0 / 12 |
| 390×844、320×640 | 小视口和最窄编辑区 | 0 / 12 |

缩放两组使用浏览器视口和设备像素比模拟可用 CSS 像素。该结果覆盖布局折行；VS Code 原生窗口缩放后的字体栅格化需在宿主中观察。上述 42 次切换未出现未捕获的脚本异常。

## 本轮针对模块行的修正

使用真实模块行渲染函数构造长模块名、长子目录和英文“临时版本偏离工程要求”状态，额外检查了 14 种宽度。原先在 421 px 视口，状态与操作按钮占去大部分列宽，模块名称区仅剩 33 px，高达 1026 px。320 px 下状态文字超出徽标可用宽度 55 px。两种问题均可能发生在文档整体宽度仍正常时。

调整后在不超过 600 px 的视口中，勾选项、模块名和操作按钮占首行，状态在下方使用余下宽度，可按词换行。421 px 时名称区回到 292 px、示例高度降至 128 px；320 px 时状态文字和行内容的横向溢出均为 0。样式位于扩展打包复用的[模块行样式表](../workbench.css)。

## 主机工具密度修正与复测

初次实测中，5 个工具的名称、用途、值与来源分散在四行，下一块“构建进程环境”在 y=1045 才露出标题。修正后，名称、状态、用途、来源和操作共享首行，路径或环境值独占下一行。在 1920×1080 复测，主机工具面板高从 673 px 降至 413 px，下一块上移 260 px 至 y=785。首屏现在可读到 ZEPHYR_BASE、ZEPHYR_TOOLCHAIN_VARIANT 和 ZEPHYR_SDK_INSTALL_DIR 三组名称及值。两种等效缩放与窄屏的 42 个页面状态也已重测，文档横向溢出均为 0。
