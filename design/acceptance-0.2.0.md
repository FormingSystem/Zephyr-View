## 现有验证的适用范围

Windows VS Code 中已走通活动栏、五页切换、查看示例清单 revision、打开 prj.conf 和复用编辑器标签。构建验证使用 project(Integration NONE) 的 CMake 测试工程，其目标创建 build-ok 标记。这个测试覆盖扩展启动任务到本地命令结束的路径，没有编译 Zephyr 固件。软件调试会话测试也未涉及硬件探针。

## 首次可用版本的验收场景

在干净的构建目录选同一份真实 Zephyr 应用和板目标，先走 west，再走无 west 的离线 CMake。核对模块及锁定版本、构建实参、最终 .config、zephyr.dts 和 ELF。分别修改一项 Kconfig 和一项 overlay，先验证放弃草稿能保留原文件，再验证保存及重新构建能产生预期差异。Windows、Linux 各执行一次并保留日志。其他未完成项仍按上表单独验收。

## 0.3.0 已验证的增量

本轮按既定构建页接入应用与板目标选择、首次配置、构建和命令预览。Z 图标打开同一个工作台，页首显示当前应用、板目标及构建方式；侧栏保留工作台入口和调试目标。手动 CMake 定义单独保存，改变板目标不会重写参数原文。构建目录已绑定其他目标时会提示选择空目录。

Windows VS Code 在两个全新的构建目录中分别验证了同一份 Zephyr 4.5.0-rc1 官方 hello_world，目标为 mps2/an386，SDK 为 1.0.1。测试从实际活动栏进入，选应用，通过 Zephyr 的本地板数据库搜索并选择完整板目标，点击配置和构建，核对 ELF 文件头、.config、zephyr.dts，并从结果区打开生成配置。

| 构建入口 | 验证条件 | 观察结果 |
| --- | --- | --- |
| west | 已有本地 west 工作区、工具链和模块 | west 配置和构建成功，生成 ARM ELF |
| CMake | 独立应用目录，Python 环境和 PATH 都没有 west，通过 ZEPHYR_MODULES 指向本地 cmsis_6 | 缓存记录 WEST-NOTFOUND，配置并构建成功，生成 ARM ELF |
