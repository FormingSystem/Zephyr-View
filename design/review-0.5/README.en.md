# Zephyr Extension 0.5.0 page-by-page design comparison

[简体中文](README.md) | **English**


This page preserves the 0.5.0 acceptance record. See the [current review](../review/README.en.md) for the vertically arranged four-page workbench.

The review used the independent extension's VSIX. The installed package ran in a separate VS Code profile on Windows, with the original HTML open in Edge. The HTML viewport was set to the editor width to compare headings, navigation, groups and actions. All screenshots are 1920×1080. CSS pixel dimensions depend on display scaling and sidebar width.

## Measurements and observations

- At an editor width of about 1178 CSS pixels, computed styles were compared page by page. Main headings were about 35.35px, group headings 16px and navigation 15px. Sampled font sizes, line heights and left padding differed by less than 0.1px.
- Each of the five pages was checked at about 722, 458 and 298 CSS pixels. Bounds of sibling navigation buttons, method switches, header controls, tool rows and build target rows showed no overlap or horizontal page overflow. At the narrowest width, the navigation itself can scroll horizontally.
- Graph zoom was tested at 75%, 100%, 125%, 150% and 200%. Against graph width at 100% in the same window, measured width differed from the displayed scale by less than 1.5 percentage points. The earlier 200% zoom bug, where the vertical scrollbar reduced graph width further, was corrected.
- On both west and CMake paths, searching for `mps2an386` found `mps2/an386`. Selecting it in the CMake test application displayed the complete qualified name in the target row. The west workspace discovered `hello_world` using `tests.yaml`.
- In a temporary application, changing `CONFIG_GPIO` from `y` to `n` left the on-disk value intact when staged. Save to Project changed the file. The real west workspace was used only to read target candidates.
